# organiz_ia

A Flutter pantry management prototype (Organiz.IA).

This README provides a short code review summary and step-by-step instructions to run and test the app locally. The project supports local-only operation (using SharedPreferences) and optional Firebase sync (Firestore, Auth, Storage) when configured.

---

## Quick code review (issues and current status)

Summary of important points discovered while reviewing the code:

- Firebase initialization is made resilient: when `lib/firebase_options.dart` is not configured the app skips Firebase on web and falls back to local-only mode. The app currently uses a `DefaultFirebaseOptions.isConfigured` flag (false by default) to detect whether Firebase options were generated by the FlutterFire tooling.

- The `FirebaseService` (lib/services/firebase_service.dart):
  - Initializes Firebase (with or without explicit options) and exposes anonymous sign-in, sign-out, saving and deleting pantry items, and a stream of pantry items from Firestore.
  - If Firebase is not available or initialization fails, caller code (PantryProvider) falls back to local storage and the app remains usable.

- The `PantryProvider`:
  - Uses SharedPreferences for local persistence (LocalStorageService).
  - Subscribes to Firestore item stream when anonymous sign-in succeeds and keeps local data in sync.
  - Cancels the remote subscription on dispose to avoid leaks.

- Potential runtime concerns to be aware of:
  1. If Firebase is not configured and you want remote sync, follow the Firebase setup steps below. Until then the app will run in local-only mode.
  2. The code uses dart:io's File type for photo upload helper; when running on web this will not work — the app is targeted to mobile (Android/iOS).
  3. The example `firebase_options.dart` shipped in the repo intentionally reports not configured. Use the FlutterFire CLI (`flutterfire`) or the Firebase console downloads to provide the real file.
  4. The app assumes the camera is available for barcode scanning. On an emulator you may need to supply a camera feed or use the barcode lookup text field instead.
  5. Personalization settings such as pantry name, default expiry days, and shelf layout are stored locally for this device and developer only. The app color palette is defined in code (lib/main.dart) and is not changed from Settings.

## Quick local-only test (no Firebase)

**Note:** Firebase is optional. This section focuses on testing the app locally without any Firebase backend. All your pantry data is saved locally on your device.

1. Open a terminal and go to the project directory:

   cd C:\Users\lucia\summercoding\organiz.ia\organiz_ia

2. Get dependencies:

   flutter pub get

3. Run the app:
   - Android emulator / iOS simulator / physical device:

     flutter run

     If you run on a real phone, connect it via USB and enable developer mode.
     Use `flutter devices` to confirm the phone is available.

     If you only have one device connected, you can also use:

     flutter run -d <device-id>

     On Android you may need to accept USB debugging prompts, and on first launch you may need to grant camera permissions for barcode scanning.
     If the app launches but the Sync button appears to do nothing, check the terminal log for Firebase initialization issues or missing `firebase_options.dart`.

   - Chrome (web):

     flutter run -d chrome

   Note: On the web the camera scanner may not work the same as on mobile. Use the Scan screen's manual barcode field when testing on Chrome.

4. Test the app features:
   - Home: the main screen lists items grouped by expiry (default). Add an item with the + button.
   - Add item: fill name, brand, barcode (optional), pick expiry date, store and location, pick grid row and column, then add.
   - Pantry Map: open the Map tab to see items placed into the grid for each location. The app now treats Freezer items as three drawers and Fridge items as five shelves plus a door and two drawers.
   - Calendar: open the Calendar tab to view expiry counts for the next 7 days and see items sorted by expiry.
   - Scan: use the Scan tab to enter a barcode manually and press "Lookup product" to query Open Food Facts. If your device/emulator has a camera configured you can press Scan to use the camera. On Chrome prefer manual barcode entry. If the barcode lookup returns no product, use the fallback button to add the item with the scanned barcode. If a product is found, the Add screen can be opened with the product data prefilled.
   - Settings: personalize the app for yourself by setting your pantry display name, default expiry days, and shelf locations. These settings are saved locally and are intended for your development device only.
   - Barcode product autofill: enable "Open Add screen after lookup" or "Auto-add product when found" to fill the Add Item form automatically on successful barcode lookup.

5. Test on Android mobile:
   - Connect your phone over USB and enable developer mode. Allow USB debugging when the phone prompts.
   - Run `flutter devices` to confirm Android is detected.
   - Start the app with `flutter run` or `flutter run -d <device-id>`.
   - Accept any permission prompts on the device, especially camera permissions if you want to test barcode scanning.
   - If the Sign in button does not work, review the terminal output for Firebase configuration or network errors.
   - Map personalization: in Settings, add or rename shelf locations and choose the number of rows/columns for each shelf to match your real pantry layout.
   - Barcode product autofill: enable "Open Add screen after lookup" or "Auto-add product when found" to fill the Add Item form automatically on successful barcode lookup.

5. Run the unit/widget test:

   flutter test

## How to design/customize screen layout

Tips to create the screen layout you want, and how to adapt the app UI to different device sizes:

- Use LayoutBuilder for responsive layout
  - Wrap widgets in a LayoutBuilder and use BoxConstraints to switch between single-column mobile and multi-column tablet/desktop layouts.
  - Example: if constraints.maxWidth > 800 show a two-column layout with the map and a side panel; otherwise stack vertically.

- Use MediaQuery for quick device metrics
  - MediaQuery.of(context).size returns the screen size. Use it to compute grid cell sizes or to change card padding.

- Grids and shelves
  - Each shelf uses a GridView.builder with crossAxisCount equal to the configured number of columns for that shelf.
  - For responsive cell sizing, compute the available width and divide by column count to get a square cell size, or use childAspectRatio.
  - If you want some cells larger than others, consider using a staggered grid package or custom layout.

- Touch targets and spacing
  - Use at least 44–48 px for interactive elements (buttons, tappable tiles) to make the UI comfortable on mobile.
  - Use EdgeInsets.symmetric(horizontal: 16, vertical: 12) for general padding.

- Theming and visual polish
  - Change the app color seed in lib/main.dart using ColorScheme.fromSeed.
  - Adjust CardTheme, ElevatedButtonTheme, and InputDecorationTheme centrally in ThemeData to keep consistent visuals.
  - Use Material 3 components (useMaterial3: true) for modern appearance; the project already uses Material 3.

- Customizing colors, icons, typography, and layout
  - Colors: open lib/main.dart and change the app color values directly in the theme. The current color palette is defined in code, not through the Settings screen.
  - Icons: replace `NavigationDestination` icons in lib/main.dart, swap `Icons.*` for your preferred built-in icons, or add custom SVGs with the flutter_svg package.
  - Typography: define `textTheme` in ThemeData, or add custom fonts in pubspec.yaml under `fonts:` and reference them in `TextStyle(fontFamily: 'YourFont')`.
  - Layout: use `LayoutBuilder` and `MediaQuery.of(context).size` to change the UI for wider screens. For a full redesign, move section cards into a responsive `GridView` or split the screen into two columns.
  - Assets: add image or icon assets to `assets/` and list them in pubspec.yaml. Use `Image.asset('assets/your_icon.png')` for custom visuals.

- Animations and transitions
  - Use Hero widgets when navigating from a list/card to the detailed Add/Edit screen to create smooth transitions.
  - For small animations use AnimatedContainer and AnimatedOpacity.

- Map customization ideas
  - Per-location photo backgrounds: render an Image beneath the Grid and apply a semi-transparent overlay to keep text readable.
  - Freezer locations named "Freezer" are shown as three drawers, and Fridge locations named "Fridge" are shown as five shelves, a door, and two drawers. Use those names when adding locations to match your real layout.
  - Color-code shelves or items by category or expiry state using consistent color tokens from the theme.
  - Add a compact "Arrange" mode where tapping items shows move handles or allows selecting multiple items to reassign locations.
  - Calendar-style expiry preview: show the next 7 days with counts of expiring products, or build a full monthly grid to visualize dates.

- Testing layout changes
  - Use `flutter run -d chrome` and the browser devtools to resize the window quickly.
  - Use `flutter run` on a device emulator with different device profiles (Pixel, iPhone, tablet) to validate touch and density.

## Enable Firebase (optional)

**Important:** Firebase is entirely optional. The app works perfectly without it using local storage only. Skip this section if you don't want to set up Firebase.

To use remote sync, authentication and storage, configure Firebase and generate `lib/firebase_options.dart`.

1. Create a Firebase project in the Firebase console: https://console.firebase.google.com/
2. Register Android and/or iOS apps in the project.
   - For Android, download `google-services.json` and place it under `android/app/`.
   - For iOS, download `GoogleService-Info.plist` and add it to `ios/Runner` in Xcode or copy into `ios/Runner/`.
   - If you are testing on Android, make sure the Android package name matches the one in your Firebase app registration.

3. Recommended: use the FlutterFire CLI which generates `lib/firebase_options.dart` automatically and wires platform config:

   dart pub global activate flutterfire_cli
   flutterfire configure --project="<your-firebase-project-id>"

   This will generate or update `lib/firebase_options.dart`. After generation, `DefaultFirebaseOptions.isConfigured` will be true.

4. Alternatively, create `lib/firebase_options.dart` manually using the Firebase options for each platform (follow the FlutterFire docs).

5. After configuring Firebase, rerun `flutter pub get` and restart the app.
   - In Settings, press Sign in to authenticate anonymously.
   - If the button still appears to do nothing, open your terminal to watch log output or run `flutter run` again and inspect the console messages for Firebase initialization errors.

5. Re-run `flutter pub get` and `flutter run`.

6. In Settings screen press Sign in to perform anonymous sign-in. After sign-in the app subscribes to the Firestore collection `users/<uid>/pantryItems` and will sync local changes.

Notes:
- Ensure Firestore rules allow read/write for the test accounts you use (for quick testing you can temporarily allow open rules, but use secure rules for real apps).
- For storage, ensure Firebase Storage rules allow upload for your test users.

## Troubleshooting

- "flutter command not found": ensure Flutter is installed and added to PATH, then restart the terminal.
- Firebase errors at startup: check `lib/firebase_options.dart` — if it's not configured the app will continue using local storage. To get remote sync working, follow the Firebase setup above.
- Barcode camera doesn't start in emulator: either run on a physical phone or use the manual barcode lookup field in the Scan screen.
- If network calls to Open Food Facts fail, verify you have an internet connection and the API is reachable.
